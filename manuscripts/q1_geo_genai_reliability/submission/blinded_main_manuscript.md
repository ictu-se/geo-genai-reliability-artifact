# From Map-Like Images to Trustworthy Cartographic Artifacts: A Cross-Paradigm Reliability Audit of Geo-Generative AI

## Abstract

Generative AI is entering cartography through text-to-map image synthesis, remote-sensing-to-map translation, LLM-generated GIS code, multimodal design agents, and specialized map-design assistants. Yet current evaluations often ask whether outputs look map-like, while practical map production requires artifacts that remain geographically grounded, spatially coherent, reproducible, editable, and auditable. This paper proposes an artifact-aware reliability framework for GeoAI map generation and stress-tests it across three public artifact families: paired text-map image data, remote-sensing-to-map tiles, and LLM/code-generated choropleth maps. The framework treats generated maps as chains linking source data, prompts or captions, conditioning inputs, generated intermediate objects, rendered outputs, validation traces, and repair histories. We operationalize this view through dataset reproducibility audits, caption-fidelity heuristics and local VLM review, geospatial linting, tile-edge continuity metrics, leakage-guarded generated-output baselines, code-execution checks, screenshot-level cartographic QA, evaluator adjudication queues, and validator-gated repair loops. Results show that reliability failures emerge at different links in the chain: caption grounding is uneven, cascade-reference coverage is incomplete, lightweight learned remote-sensing-to-map baselines improve some image metrics while smoothing cartographic detail, and plausible generated GIS code can fail to produce complete map artifacts. A validator-gated repair sweep completes 25 of 40 previously incomplete choropleth cases, but also shows why repair must be audited as evidence rather than assumed as success. The study offers a reproducible scaffold for comparing, diagnosing, and improving GeoAI map-generation workflows.

Keywords: generative AI, cartography, GeoAI, map generation, evaluation, reproducibility, cartographic quality, LLM agents, remote sensing, choropleth maps

## 1. Introduction

Generative AI is beginning to change cartographic production from two directions at once. Image-generation systems can synthesize map-like raster outputs from text, vector constraints, or remote-sensing imagery, while LLM-based agents can write GIS code, assemble thematic maps, and revise outputs after execution. This development sits inside a longer GIScience tradition in which geographic information is not just data storage but a formal representation of spatial objects, relationships, uncertainty, and process (Goodchild, 1992; Janowicz et al., 2020). It also sits inside a cartographic tradition in which maps are designed arguments about classification, symbolization, scale, projection, legibility, and intended use. For that reason, generated cartographic outputs cannot be evaluated as ordinary pictures alone.

Recent GeoAI and cartographic AI work shows both the promise and the fragility of this shift. Latent-diffusion and ControlNet-style models provide a technical basis for spatially conditioned image synthesis (Rombach et al., 2022; Zhang et al., 2023). Map-specific work then adapts this general progress to text-promptable maps, remote-sensing-to-map translation, LLM-generated choropleth workflows, VGI-driven mapping agents, multimodal style agents, and color-design assistants (Zhang et al., 2025; Sun et al., 2025a; Pannoon and Netek, 2025; Song et al., 2025; Wang et al., 2025; Yang et al., 2025). Review and agenda papers converge on a similar concern: GeoAI mapmaking needs stronger evidence about spatial reasoning, reproducibility, transparency, uncertainty, and domain-specific validation before plausible outputs can be treated as trustworthy cartographic artifacts (Kang and Wang, 2026; Kausika and van Altena, 2025; Sun et al., 2025b).

The key problem is that current evaluation practices are fragmented across artifact types. Image-generation papers often emphasize visual realism, pixel similarity, or qualitative examples; agent papers often report screenshots or case studies; cartographic subtask papers use specialized user studies or task-specific metrics. These approaches are valuable, but none is sufficient for map production as an artifact chain. A raster tile can score well under image similarity while breaking road continuity or washing away labels. A caption can be fluent while omitting spatial relations needed for faithful text-to-map generation. A Python script can appear plausible, or even exit with return code 0, while joining the wrong field, dropping CRS metadata, producing a blank map, or failing to write the requested artifacts. Conversely, a failed run may still be scientifically useful if it exposes a reproducible failure mode. This is why dataset documentation, model reporting, and computational reproducibility principles matter directly for Geo-GenAI evaluation (Wilkinson et al., 2016; Sandve et al., 2013; Peng, 2011; Gebru et al., 2021; Mitchell et al., 2019).

This paper's novelty is to shift the unit of evaluation from a generated map image or a single model run to the cartographic artifact chain. We define that chain as the linked sequence of source data, prompt or caption, conditioning input, generated intermediate artifact, rendered output, validation trace, and repair history. The same reliability requirement appears differently across paradigms. Text-to-map systems require caption grounding, image-feature alignment, and evaluator robustness. Remote-sensing-to-map systems require split integrity, scale-aware conditioning, generated-output baselines, and tile-edge continuity. LLM-code systems require executable code, schema and CRS validity, complete output artifacts, screenshot-level map QA, and validator-gated repair. Treating these as one artifact-chain problem makes failures comparable without pretending that all paradigms should share a single metric.

The empirical contribution is a reproducible cross-paradigm audit rather than a new generator architecture. We stress-test three public artifact families: paired text-map image data, remote-sensing-to-map tiles, and LLM/code-generated choropleth maps. Across these families, we quantify dataset availability, split coverage, caption structure, cascade-reference completeness, edge continuity, geospatial lint findings, generated-code execution, rendered-output QA, VLM/human-label readiness, and repair-loop behavior. The novelty is therefore methodological and evidentiary: the paper shows how to turn broad claims about trustworthy Geo-GenAI into inspectable checks, negative evidence, positive controls, and repair records. The results are not intended as a leaderboard. They show which links in the artifact chain are already auditable from public materials, which links remain under-validated, and how future GeoAI map-generation systems can report stronger evidence.

The paper is organized around five research questions:

RQ1. How reproducible are public Geo-GenAI map-generation artifacts when evaluated as data-code-model-output chains?

RQ2. Do text-to-map map datasets provide captions that are sufficiently grounded for faithful map generation and evaluation?

RQ3. How should remote-sensing-to-map generation be evaluated beyond file availability and visual plausibility?

RQ4. Can LLM-generated GIS/code maps produce complete, executable, cartographically valid artifacts under basic and rule-guided prompting?

RQ5. What cross-paradigm failure taxonomy can unify text-to-map, remote-sensing-to-map, and LLM-code map generation?

### Contributions

1. We synthesize recent Geo-GenAI map-generation work into an artifact-aware taxonomy spanning text-to-map images, remote-sensing-to-map translation, LLM-generated GIS/code maps, style agents, and design-subtask assistants.
2. We implement a reproducibility audit for public artifacts, covering dataset size, file counts, code availability, and evaluation blockers.
3. We audit MapGenerator image-caption pairs using file-level heuristics, deterministic visual proxies, contact sheets, VLM pilots, evaluator-robustness checks, and calibrated multi-judge consensus.
4. We audit SCGM/CSCMG split coverage and introduce tile-edge continuity metrics plus deterministic retrieval, lightweight learned forest, compact neural MLP, local-context ridge, convolutional filter-bank ridge, and patch-embedding retrieval generated-output baselines.
5. We audit choropleth code/mapmaking materials using geospatial linting, released artifact checks, screenshot-level QA, and deterministic reference baselines.
6. We implement an expanded 12-task choropleth code-generation benchmark, one-pass repair, validator/reference positive controls, a matched repair-model suite, and a full iterative validator-gated repair sweep for previously incomplete artifacts.

## 2. Background and Related Work

### 2.1 Image-Based and Design-Oriented Map Generation

Controlled diffusion approaches use vector data, remote sensing imagery, reference tiles, or text prompts to constrain generated map images. These systems are strongest when spatial control is explicit. Latent-diffusion and ControlNet-style workflows can learn cartographic appearance from map tiles while using semantic or vector-derived inputs to reduce hallucination. Remote-sensing-to-map methods add scale conditioning and contextual references, reflecting the fact that map generalization is scale-dependent.

The controlled-generation literature is valuable because it recognizes that maps are not ordinary pictures. Spatially conditioned diffusion reduces some hallucination risk, but it shifts the remaining problem toward topology, line continuity, label reintegration, and production workflow integration. SCGM/CSCMG-style artifacts take a different route: remote-sensing imagery and cascade references condition multi-scale map generation. That framing is closer to cartographic generalization, because the target is not one isolated image but a coherent set of tiles across scales.

Text-to-map image generation sits between these two approaches. MapGenerator-style datasets pair natural-language descriptions with map images, making text prompts the main control signal (Zhang et al., 2025). This is useful for studying promptable map synthesis, but it creates a new reliability dependency: if captions are underspecified, generic, or visually unfaithful, then both training and evaluation become noisy. A model trained on fluent but weakly grounded captions may learn map-like appearance without learning robust spatial semantics.

The main open problems across image-based systems are topology, text, scale, and tile consistency. Roads may break at tile boundaries, buildings may be hallucinated or omitted, natural terrain may be generalized poorly, and labels are often avoided rather than solved. These limitations motivate metrics beyond FID or visual similarity. A generated tile must be evaluated not only as an image, but also as a spatial neighbor, a scale-specific generalization, and a cartographic artifact with features that should connect across boundaries.

### 2.2 Agentic Cartography and Evaluation Gap

LLM agents can retrieve data, write GIS code, call mapping libraries, and revise outputs. This paradigm is attractive because it preserves authoritative geodata and produces editable code or style artifacts. However, LLM agents are brittle: they may use wrong column names, ignore CRS, choose poor classifications, omit map elements, or produce code that executes but generates a misleading map. Multimodal agents add visual critique, but map-specific evaluation remains weak.

Recent agent systems illustrate both the promise and the evaluation gap. VGI mapping agents show that an LLM can decompose a user request, retrieve OSM-like data, run GIS operations, and render thematic maps (Song et al., 2025). CartoAgent shows that multimodal agents can manipulate style artifacts while preserving geometry in a vector/style ecosystem (Wang et al., 2025). GeoAI work more broadly argues that mapmaking systems should be spatially explicit and result-aware: they should inspect their outputs and revise them, not merely emit workflows. These directions converge on the same requirement: the generated artifact must be validated after execution or rendering.

For LLM-code cartography, post-generation validation is especially important. Code can look plausible while using a nonexistent field, assuming a CRS, hard-coding a path, or silently failing to write the requested output. A process can exit with return code 0 but still produce an incomplete map. Conversely, a deterministic reference script can prove that the data and environment are sufficient, separating model failure from benchmark failure. This paper's choropleth benchmark is designed around that distinction: generated code, execution logs, artifacts, diagnostics, repair attempts, and screenshots are all treated as evidence.

**Cartographic design subtasks.**

Other work targets color schemes, label placement, pictorial symbols, storytelling, and style transfer (Burghardt et al., 2025; Li et al., 2025b; Yang et al., 2025). These subtasks are often easier to constrain than full map generation, but they still require domain-specific evaluation. A color scheme must respect data semantics and accessibility. A label placement must avoid collisions and preserve readability. A style transfer must preserve data geometry while changing appearance.

Subtask systems are important because they expose evaluation methods that full map-generation papers often lack. MapColorAI evaluates color-scheme generation through user interaction and cartographic color concepts (Yang et al., 2025). Label-placement benchmarks turn label decisions into coordinate predictions with benchmarkable error. Pictorial-map and storytelling systems focus on expressive communication rather than spatial reconstruction (Burghardt et al., 2025; Li et al., 2025b). These tasks are narrower than full map generation, but their evaluation questions are sharper: Did the symbol support the map purpose? Did the label collide? Did the color ramp fit the data type? Did the narrative transformation preserve spatial meaning?

The lesson for full Geo-GenAI map generation is that cartographic quality is multi-component. A map can pass an image-similarity metric while failing labels, legends, accessibility, or data joins. A style agent can preserve geometry while choosing ambiguous symbology. A color agent can create a pleasing palette that fails perceptual ordering. Therefore, an artifact-aware benchmark should not collapse all quality into one score. It should track which part of the artifact chain was generated and which cartographic obligation applies to that artifact.

**Evaluation gap.**

Across these paradigms, evaluation remains fragmented. Image-generation papers often use image metrics and qualitative inspection. LLM-agent papers often use case studies and screenshots. Cartographic subtask papers may use user studies or task-specific metrics. Recent review and perspective work makes the same point at a broader level: GenAI is promising for cartography, but spatial reasoning, reproducibility, domain-specific validation, and governance remain open problems (Kang and Wang, 2026; Kausika and van Altena, 2025; Sun et al., 2025b). What is missing is an artifact-aware framework that asks: what type of artifact is generated, what can go wrong for that artifact, and what validation method can detect it?

Table 17 summarizes this literature in terms of generated artifact, control signal, evaluation style, and remaining reliability gap. The pattern is consistent. Controlled diffusion papers have stronger spatial conditioning but still need topology and continuity checks. Text-to-map papers need caption-fidelity audits before caption-based generation can be trusted. LLM-agent systems preserve editable geodata but need execution, linting, and rendered-output QA. Design-subtask systems often have clearer rubrics, but their narrowness means they cannot stand in for full map-production reliability.

This paper's contribution is not to replace those paradigms with one model. Instead, it proposes a common reliability vocabulary across them. Reproducibility asks whether the public artifact chain can be reconstructed. Data grounding asks whether prompts, captions, and schemas refer to the actual map data. Spatial faithfulness asks whether generated outputs preserve geography and tile continuity. Artifact validity asks whether files, code, and rendered maps exist and parse. Cartographic completeness asks whether maps contain the design elements needed for use. Repairability asks whether failures can be detected, corrected, and revalidated. The experiments below operationalize these dimensions on public Geo-GenAI artifacts.

## 3. Conceptual Framework: Generated Maps as Artifact Chains

We define a Geo-GenAI map artifact chain as the sequence:

1. source geographic data;
2. task prompt or caption;
3. conditioning information or tool schema;
4. generated intermediate artifact, such as image, code, style, or workflow spec;
5. rendered map output;
6. validation trace and repair history.

Each link has different failure modes. A caption may be underspecified. A remote-sensing tile may be paired correctly but lack cascade references. A generated code file may execute but join the wrong field. A rendered image may have a legend but use an inappropriate color ramp. A map may be visually plausible but not geographically faithful.

This framework leads to three evaluation principles:

- Evaluate the artifact type, not just the final screenshot.
- Preserve geospatial metadata and provenance during evaluation.
- Use repair loops only when their deterministic and model-generated components are separately reported.

**Reliability dimensions.**

We operationalize reliability through five dimensions.

First, reproducibility asks whether a reader can obtain the same inputs, code, models, and evaluation procedure. This is broader than data availability. A repository can contain images but omit model weights, prompt versions, split definitions, or execution environments.

Second, data grounding asks whether generated artifacts are anchored to the provided geographic data. For an image model, this means objects and relations in the caption or conditioning data should be reflected in the image. For an LLM-code map, it means the script should use the provided files and columns rather than inventing new schemas.

Third, spatial faithfulness asks whether geometry, topology, scale, and neighborhood relationships are preserved. For RS-to-map tiles, this includes edge continuity across adjacent generated tiles. For choropleths, it includes CRS handling, geometry validity, and correct joins.

Fourth, cartographic completeness asks whether an output satisfies the conventions needed for map use: title, legend, source note, color ramp, classification, labels or tooltips where requested, and readable layout.

Fifth, artifact validity asks whether the generated object exists in the required form and can be inspected or reused. A Python script that exits successfully but creates no PNG, HTML, or diagnostic file is not a valid map artifact. This dimension is especially important for LLM-code systems, where textual plausibility and execution status can diverge from usable output.

**Failure model.**

The framework assumes that Geo-GenAI failures can occur before, during, and after generation. Pre-generation failures include incomplete releases, ambiguous captions, missing CRS metadata, and inconsistent split definitions. Generation failures include hallucinated features, broken tile continuity, missing imports, wrong filenames, and wrong columns. Post-generation failures include blank images, missing legends, invalid HTML, unparseable diagnostics, and repair loops that improve code appearance without producing valid artifacts.

This failure model motivates the paper's experimental design. Each experiment targets a different point in the artifact chain: reproducibility audit for release integrity, caption proxy review for data grounding, SCGM continuity and retrieval for spatial faithfulness, and choropleth execution/artifact QA for editable map generation.

**RQ-to-evidence matrix.**

The study is organized around a matrix rather than a single benchmark score. RQ1 concerns reproducibility and is answered with dataset inventories, claim-versus-artifact tables, and blocker classification. RQ2 concerns caption fidelity and is answered with deterministic caption heuristics, visual proxy review, and a local VLM sanity check. RQ3 concerns remote-sensing-to-map spatial faithfulness and is answered with split coverage, cascade-reference coverage, edge continuity, leakage-guarded retrieval baselines, lightweight learned forest, compact neural MLP, local-context ridge, convolutional filter-bank ridge, patch-embedding retrieval baselines, and generated-output image metrics. RQ4 concerns LLM-code cartography and is answered with geodata linting, generated-code safety scanning, execution logs, artifact scoring, screenshot QA, VLM visual review, and repair-loop experiments. RQ5 concerns cross-paradigm evaluation and is answered by mapping each paradigm to its artifact type, dominant failure modes, and appropriate validation layer.

This matrix is important because no single metric is meaningful across all Geo-GenAI map-generation paradigms. A text-to-map raster image cannot be evaluated with the same contract as a Python script that should create a Folium map and diagnostics. A remote-sensing-to-map tile cannot be judged only by whether it resembles one target tile; it must also preserve tile-neighborhood behavior. A choropleth script cannot be considered successful because it mentions the correct shapefile; it must run, join data correctly, and produce inspectable artifacts. The paper therefore treats evaluation as a set of contracts, each matched to an artifact family.

We distinguish three strength levels of evidence. The first is file-level evidence: a dataset, script, image, or HTML file exists and is non-empty. The second is structural evidence: the artifact has expected metadata, dimensions, columns, output names, or parseable content. The third is cartographic evidence: the artifact visually and semantically satisfies a mapping task. Much of the current Geo-GenAI literature stops between the first and second levels. This study pushes each paradigm toward the third level where possible, while explicitly labeling proxy and pilot layers when they are not yet human-validated ground truth.

## 4. Data and Artifacts

The study uses five available artifact groups. Table 1 summarizes the inventory and Table 2 summarizes reproducibility.

The generated tables are maintained as part of the reproducibility package.

The artifact groups were selected because they represent distinct Geo-GenAI paradigms and because enough released material exists to run at least one reproducible audit. The study therefore does not claim to cover all Geo-GenAI papers. It uses available evidence to build and stress-test an evaluation framework that can later be extended to additional systems.

**SCGM / CSCMG.**

The SCGM/CSCMG dataset is the largest available artifact group, containing remote-sensing images, target map tiles, and cascade references. The base `rs_256` and `map_256` pairs match one-to-one by filename in both train and validation splits. Cascade-reference folders are smaller than the base pair set, so reproduction must either filter to complete-reference subsets or implement missing-reference logic.

**MapGenerator.**

MapGenerator provides paired map images and natural-language descriptions. The available release contains 750 training pairs and 100 evaluation pairs. All checked images exist and are 1024 by 1024 pixels. This dataset is lightweight enough for immediate caption-fidelity and image-text alignment experiments.

**Choropleth and benchmark materials.**

The choropleth materials contain Portugal wildfire data, shapefiles, static PNG outputs, interactive HTML outputs, and prompt/code artifacts from a ChatGPT-4 choropleth case study (Pannoon and Netek, 2025). This is a strong low-compute benchmark for LLM-generated GIS maps because the task is concrete, the data are released, and errors such as CRS, geometry validity, joins, and map completeness are measurable.

**GeoGuard benchmark.**

The GeoGuard LA County benchmark is included as an evaluator testbed, not as a public artifact from the surveyed literature. It is useful for workflow-spec validation and deterministic GIS execution experiments.

**Claim table and inclusion criteria.**

The claim-vs-artifact table records whether available materials support the scale and reproducibility claims noted in the survey notes. This table is deliberately conservative. If a paper reports a dataset or user study but no reproducible artifact is available to the audit, the status is marked as not reproducible from available artifacts rather than inferred from the paper text. This prevents the manuscript from overstating evidence. It also distinguishes between artifact audit, which can be performed from preserved materials, and full experimental reproduction, which may require missing weights, proprietary prompts, or external APIs.

**Inclusion and exclusion criteria.**

The empirical scope is deliberately constrained to artifacts that can be inspected or executed from released materials. A system is included when it contributes to one of the paper's three map-generation paradigms and has enough released material to support at least one reproducibility, fidelity, continuity, execution, or artifact-quality audit. Papers that are purely conceptual are retained in the literature taxonomy, but they are not treated as empirical reproduction targets unless they release data, code, outputs, or benchmark descriptions. This avoids an unfair comparison between agenda papers and artifact-producing systems.

The experiments also exclude claims that would require unavailable proprietary model versions, private APIs, or unbounded manual interpretation. For example, the choropleth benchmark does not attempt to reproduce the exact historical ChatGPT interface used by the original materials. Instead, it uses the released data as a controlled benchmark for reproducible coding models and repair loops. Similarly, the SCGM experiment does not claim to reproduce the original trained diffusion model; it audits available dataset coverage and implements lightweight generated-output baselines that exercise the evaluation pipeline. These exclusions are part of the reliability argument: when exact reproduction is impossible, the paper records the blocker and substitutes a clearly labeled audit or lower-bound baseline rather than implying full replication.

## 5. Methods

The methods are designed to be lightweight, deterministic, and repeatable on a standard workstation. The aim is not to replace full model evaluation, but to create a baseline reliability layer that should precede expensive generation experiments. Every method writes machine-readable outputs so that manuscript tables can be regenerated from experiment artifacts.

### 5.1 Release, Reproducibility, and Caption Audits

We count files, sizes, readme/license availability, code availability, and evaluation blockers for each artifact group. The audit produces a dataset inventory and reproducibility matrix. This layer answers whether a reader can plausibly reproduce the claimed experiments or whether important components are missing.

The audit distinguishes data reproducibility from evaluation reproducibility. Data reproducibility means that released files exist and can be inspected. Evaluation reproducibility means that the claimed model, split, prompt, weights, or scoring procedure can plausibly be rerun. A dataset may pass the first criterion and fail the second. This distinction is important for Geo-GenAI because many releases provide example outputs without freezing the generative system that created them.

**Caption fidelity audit.**

For MapGenerator, we parse description spreadsheets, verify image existence, inspect image dimensions, and extract caption heuristics. We count mentions of roads, water, green areas, POIs, labels, directions, and intersections. We flag captions with no named feature, no direction or relation, or generic claims that no additional geographic features are present. These flags identify candidates for human or VLM review.

We add a deterministic proxy caption-fidelity review for 200 sampled pairs: 100 from MapTrain and 100 from MGEval. The sample balances heuristic-flagged and unflagged captions where possible. For each image, we compute simple visual signals for blue water-like pixels, green land-cover-like pixels, dark text/detail pixels, low-saturation bright map areas, and edge density. These image proxies are compared with caption mentions of water, green areas, roads, named features, and spatial relations. The resulting proxy score is not a ground-truth semantic label; it is a reproducible pre-screening layer for prioritizing VLM or human review.

The proxy review intentionally focuses on high-precision, low-complexity cues rather than full semantic parsing. Blue pixels are not a complete model of water, and green pixels are not a complete model of vegetation. However, mismatches between these simple signals and caption claims are useful triage indicators. For example, a caption that claims no additional geographic features while the image contains strong water or green-area signals should be reviewed. Likewise, a road-heavy caption without any directional or relational term may be less useful as a generation prompt than a caption that describes how roads intersect or orient.

As an initial model-based sanity check, we ran local VLM caption reviews on proxy-selected image-caption pairs. The strongest complete run uses `granite3.2-vision:latest` on 20 pairs: it judges all 10 MGEval pairs as supported and judges 9 of 10 MapTrain pairs as supported with one partly supported case. Mean VLM alignment scores are higher than deterministic proxy scores: 1.000 versus 0.741 for the MGEval sample, and 0.945 versus 0.667 for the MapTrain sample. A second complete run with `qwen2.5vl:3b` on the same 20-pair design is more critical: it reports mean scores of 0.880 for MGEval and 0.890 for MapTrain, marks 18 of 20 pairs as partly supported, flags unsupported claims in 18 rows, and flags omissions in 9 rows. Additional candidate judges expose evaluator brittleness: `llava-llama3:8b` produces 16 usable reviews and 4 schema errors on the same 20-pair caption panel, while `qwen3-vl:4b`, `llama3.2-vision:11b`, and `minicpm-v:latest` fail most or all schema-constrained caption-review calls. Together, these results suggest that the proxy layer is deliberately conservative and useful for triage, while also showing that single-VLM verdicts can be either overly permissive or operationally unstable. The VLM pilot should therefore be treated as a sanity check and evaluator-stress test, not as a substitute for human labels or calibrated multi-model adjudication.

We therefore add a paired agreement analysis for the two complete MapGenerator VLM runs. Granite and qwen2.5vl reviewed the same 20 image-caption pairs. They agree on low-level visible features in 73 of 79 comparable feature judgments, but they agree on exact caption-support verdicts in only 3 of 20 cases. Qwen assigns a lower alignment score in 15 of 20 cases. This pattern is useful evidence in itself: VLMs can provide a reproducible screening layer for caption grounding, but their semantic support thresholds differ enough that final caption-fidelity claims require adjudication, human labels, or explicit multi-judge rules.

We add a calibrated multi-judge consensus layer over all schema-conformant VLM reviews. The consensus layer uses only parseable rows and treats failed JSON or missing scores as coverage loss rather than imputing labels. For MapGenerator, all 20 reviewed caption pairs have at least two usable judges, with up to four usable judges for some items. Only 1 of 20 cases reaches high-confidence coarse consensus, 15 are medium-confidence, and 4 are low or insufficiently stable; the coarse consensus labels 2 cases as supported, 14 as below-supported, and 4 as discordant or tied. This strengthens the evaluator-validity claim without converting VLM outputs into human ground truth.

We also add CLIP-style image-text embedding screening for the full 200-pair proxy-review sample using `openai/clip-vit-base-patch32`. The scoring run completes all 200 pairs with no per-item errors. The mean cosine score is 0.343, with MGEval averaging 0.339 and MapTrain averaging 0.347. The CLIP score is not strongly aligned with the deterministic proxy score in this sample (overall Pearson r = -0.039), and the proxy severity groups remain close together: low-severity rows average 0.340 and medium-severity rows average 0.346. This weak association is useful evidence rather than a failure of the experiment. It shows that generic image-text embedding similarity provides a reproducible semantic screening layer, but it does not by itself resolve cartographic caption truth conditions such as missing named features, unsupported spatial relations, or omitted map labels. The final caption-fidelity claim therefore rests on convergence and disagreement across proxy review, VLM review, multi-judge consensus, CLIP screening, and the still-needed human adjudication layer.

### 5.2 SCGM Tile and Generated-Output Evaluation

For SCGM/CSCMG, we index tile filenames by zoom, x, and y. We compute base pair matching and cascade-reference coverage. For validation tiles, we compute a simple edge-continuity metric: mean absolute RGB difference between the shared borders of adjacent tiles. This creates a reference baseline for future generated tile outputs.

We also run a lightweight generated-output baseline without training a diffusion model. For 100 validation tiles, we compute color-statistic features from the validation remote-sensing tile, retrieve the nearest train remote-sensing tile from a 200-tile train candidate pool, and use the paired train map tile as the generated output. Exact tile-id matches are explicitly excluded to avoid train-validation leakage. The generated maps are scored against validation target maps using RGB MAE, RGB PSNR, a global luma SSIM proxy, and the same tile-edge continuity metric used for target maps.

The generated-output baselines are intentionally simple. They are included because they transform the SCGM track from a dataset-only audit into a generated-output evaluation. The first baseline retrieves by color statistics. The second uses a deterministic multi-feature vector composed of downsampled RGB grids, edge grids, RGB summary statistics, and color histograms. The third trains a CPU-friendly random-forest regressor from remote-sensing tile features to a low-resolution cartographic output grid, then upsamples predictions to 256 by 256 pixels. The fourth trains a compact neural MLP regressor on the same low-resolution target grid. The fifth trains a shared local-context ridge regressor that predicts each low-resolution map pixel from a 3-by-3 remote-sensing neighborhood, local edge magnitude, and normalized pixel coordinates. The sixth trains a convolutional filter-bank ridge regressor over 64-by-64 pixels using fixed Sobel, Laplacian, Gaussian, high-pass, and 5-by-5 local-context features. The seventh builds each validation output from locally retrieved remote-sensing patches and their paired train-map patches. The eighth trains a small fully convolutional RS-to-map network directly on leakage-filtered tile pairs at 64-by-64 resolution. These baselines do not reproduce the official SCGM diffusion model, but they exercise retrieval, regression, fixed-filter, local patch-transfer, and trained CNN paths. This matters methodologically: once generated-output directories exist, the same code path can score retrieval, pix2pix, ControlNet, diffusion, or SCGM reproduction outputs. The leakage guard is also part of the contribution. The first pass revealed exact tile-id overlaps between small train and validation subsets; excluding those matches prevents retrieval baselines from copying validation targets, and the learned, patch-based, or CNN baselines exclude overlapping validation tile identifiers before fitting or retrieval.

### 5.3 Choropleth Artifact QA and Repair Evaluation

For choropleth materials, we lint raw geodata for required columns, CRS, invalid geometries, empty geometries, and thematic field types. We audit released PNG and HTML artifacts for file presence, non-empty content, and coarse HTML map structure. Existing seed candidate runs are scored for execution success and required output checks.

We also create a deterministic reference baseline from the same released data. The baseline sets missing CRS metadata to EPSG:4326 when coordinates are lon/lat, repairs invalid geometries, renders a static choropleth PNG, renders an interactive Folium HTML map with district tooltips, plots the annual burned-area time series, and writes a diagnostic JSON. This reference is not a generative result; it is a validator target that defines what a successful LLM-code artifact chain should be able to produce.

For rendered artifacts, we perform a lightweight artifact QA pass. PNG outputs are checked for dimensions and nonblank dynamic range, HTML outputs are checked for Leaflet/GeoJSON/tooltip markers, and diagnostic files are checked for valid JSON. This does not replace human or VLM cartographic review, but it catches the common failure mode where code returns successfully without creating usable map artifacts.

The expanded code-generation benchmark uses 12 prompts and two prompting modes. Basic prompts state the user request with minimal data grounding. Rules prompts provide file names, known columns, known data issues, output naming conventions, CRS and geometry repair rules, and cartographic expectations. Two reproducible coding models are evaluated: `qwen2.5-coder:7b` and `deepseek-coder:6.7b`. Static safety scanning is performed before execution. Safe scripts are run in a controlled environment with benchmark input and output variables; scores require execution success, use of known files and environment variables, and task-specific artifacts such as static PNG, interactive HTML, time-series PNG, or diagnostics JSON.

This scoring design separates partial grounding from complete artifact success. A script can receive partial credit for mentioning CRS repair or using known file names, but it only becomes a complete map artifact if it executes and produces the requested outputs. This distinction prevents a common evaluation error: treating plausible generated code as successful without running it and inspecting its products.

We also implement a validator-gated iterative repair pilot for near-miss cases after the one-pass 32B repair condition. The pilot selects incomplete one-pass repairs with the highest existing scores, then feeds the previous code, runtime stderr, created-file list, failed rubric checks, task prompt, and required outputs back to `qwen2.5-coder:32b`. Each repaired script is statically safety-scanned, executed, and rescored before any next iteration is attempted. This makes the loop validator-gated rather than conversational: the model receives concrete execution and artifact-contract feedback, and progress is measured only by rerunning the repaired script.

**Screenshot-level cartographic QA.**

The file-level artifact audit does not judge whether a map is visually inspectable. We therefore add a screenshot-level QA layer for static PNGs, time-series PNGs, and interactive HTML maps. For HTML maps, the script renders each generated artifact in a headless Chromium browser and captures a screenshot. For all image-like artifacts, it computes visual proxies: image size, dynamic range, non-white coverage, color-bin diversity, edge detail, and dark text-like detail. These measures do not replace expert cartographic review, but they catch common post-execution failures such as blank outputs, tiny placeholder figures, low-detail images, and HTML maps that parse but do not render.

For the current manuscript track, screenshot-level QA is a second-stage validator after file existence and parseability. The deterministic reference baseline passes all three visual artifact checks: static choropleth, interactive HTML screenshot, and time-series figure. The validator/reference condition passes 36/36 screenshot-level checks across 12 tasks. The 32B LLM repair condition passes five static-map screenshot checks, but produces no rendered interactive HTML or time-series screenshot. Initial LLM generation produces no screenshot-level map pass. We add a reproducible VLM cartographic-quality pilot on 18 screenshot-passing artifacts: three deterministic reference artifacts, five 32B repair artifacts, and ten validator/reference artifacts. Two VLMs, `granite3.2-vision:latest` and `qwen2.5vl:3b`, review the same artifact selection. The pilot scores visible map content, readability, title presence, legend/colorbar presence, layout occlusion, choropleth appearance, and an overall verdict. It is treated as a sanity check and evaluator-sensitivity test rather than human ground truth.

We also compute paired agreement for the two choropleth VLM reviewers. Across the 18 common artifacts, exact verdict agreement is 13/18 and usable-versus-below agreement is 14/18. Agreement is strongest for the validator/reference group, where both models give the same usable-with-minor-issues verdict to all ten reviewed artifacts. Agreement is weakest for the LLM-repair static maps: exact agreement is 1/5, and no repair artifact is judged usable by both models. A third candidate judge, `llava-llama3:8b`, produces only 5 usable schema-conformant choropleth reviews out of 18, with 13 parse errors, so it is not included in the agreement panel. This confirms that the VLM layer is most valuable as a sensitivity test around visual QA, not as a calibrated expert score.

**Reproducibility package and traceability.**

Every experiment writes machine-readable outputs before manuscript tables are generated. Dataset audits write CSV inventories and JSON summaries. Caption audits write pair-level CSVs, summary JSON, and contact sheets. SCGM experiments write manifests, metric CSVs, summary JSON, generated maps, and contact sheets for retrieval, learned forest, neural MLP, local-context ridge, convolutional filter-bank ridge, and patch-embedding retrieval outputs. Choropleth experiments write generated code, safety-scan CSVs, run manifests, stdout/stderr logs, metadata JSON files, artifact QA tables, screenshot QA tables, VLM review tables, and repair-loop summaries. Manuscript tables are then synthesized from these outputs rather than hand-entered.

This traceability matters for two reasons. First, it makes the manuscript auditable: a table value can be traced back to a script output and, in many cases, to a specific run record. Second, it reduces the risk of rhetorical evaluation drift. If a script executes but fails to write `map_static.png`, the score table records that failure even if the generated code appears plausible. If a VLM labels a screenshot as usable, the VLM model and reviewed artifact identifier are recorded so that the label can be revisited. The package is therefore designed as a living evidence base for the manuscript, not only as a one-time analysis dump.

## 6. Results

### 6.1 Release and Caption Findings

The available artifact inventory contains one large remote-sensing-to-map dataset, one lightweight text-to-map dataset, one code-generated choropleth material set, one ControlNet-style code repository without original training data, and one workflow benchmark. Reproducibility varies by artifact type. File-level data are often available, but exact evaluation reproduction is blocked by missing model weights, incomplete paper access, API/model version drift, or compute requirements.

This result supports RQ1. The most important pattern is not simple absence or presence of data, but unevenness across the artifact chain. SCGM provides a large available dataset, but cascade-reference availability is incomplete. MapGenerator provides images and captions, but the available train count differs from the count recorded in survey notes. The choropleth repository provides data and released outputs, but the original ChatGPT model/version environment is not frozen. These cases show why reproducibility tables should record data, code, model, and evaluation availability separately.

**MapGenerator caption audit.**

MapGenerator contains 750 training pairs and 100 evaluation pairs in the available release. No missing images were found, and all images are 1024 by 1024 pixels. Captions average about 51 words for training and 54 words for evaluation. Heuristics flag a substantial number of captions that lack explicit spatial relation terms or make generic negative claims. These are not necessarily errors, but they identify where text-to-map prompts may be under-constrained for faithful generation.

The proxy caption-fidelity review shows that most sampled pairs are broadly consistent under coarse visual checks, but it also identifies review-worthy cases. In the 100-pair MGEval sample, the mean proxy fidelity score is 0.946, with 34 medium-severity and 66 low-severity cases. In the 100-pair MapTrain sample, the mean proxy fidelity score is 0.914, with 53 medium-severity cases, 46 low-severity cases, and one high-severity case. The most common proxy issues are generic no-feature claims on visually rich maps, possible water omissions, and road captions that lack explicit relation terms. These results support using MapGenerator as a caption-fidelity benchmark, but also show why VLM or human validation is needed before treating caption heuristics as true semantic errors.

This result supports RQ2. The dataset is usable, but caption fidelity cannot be assumed from file completeness. A caption can be long and fluent while still omitting spatial relations, making generic negative claims, or underspecifying the image. The proxy review provides an economical way to prioritize a smaller set for human or VLM adjudication. The multi-model VLM pilot shows that model-based adjudication is feasible, but the disagreement between Granite and qwen2.5vl, together with qwen3-vl parsing failures, reinforces the need for calibrated prompts, multiple independent judges, or human agreement before treating VLM scores as ground truth. Together, the proxy and VLM layers turn caption quality into a measurable artifact property rather than an informal impression.

### 6.2 SCGM Coverage and Continuity

SCGM/CSCMG base RS-map pair coverage is complete for train and validation splits. Cascade references are incomplete relative to the base set. On validation tiles, target map tiles have much lower edge RGB discontinuity than remote-sensing images, as expected for rendered cartographic tiles. This baseline can be used to evaluate whether generated map tiles preserve the smooth boundary behavior of target maps.

The lightweight color-stat retrieval baseline creates 100 validation map outputs from 200 train candidates after excluding 6 exact tile-id matches that would have leaked validation targets. It is intentionally weak but useful as a generated-output lower bound: mean RGB MAE is 16.77, mean RGB PSNR is 19.93, and mean global luma SSIM is 0.245. Generated edge continuity is much worse than the target map reference baseline, with mean border difference 20.09, compared with about 1.85-2.75 for adjacent target map tiles. This confirms that the SCGM evaluation code can now score generated outputs, not only ground-truth data.

The multi-feature retrieval baseline exposes metric sensitivity. It improves mean global luma SSIM from 0.245 to 0.290, but worsens mean MAE from 16.77 to 21.68, mean PSNR from 19.93 to 19.19, and generated edge continuity from 20.09 to 24.09. In other words, a richer remote-sensing similarity feature does not automatically produce better cartographic outputs under every metric.

The learned forest baseline changes the trade-off again. After excluding six overlapping train/validation tile identifiers, it trains on 194 samples and produces 100 validation outputs. It improves mean global luma SSIM to 0.409 and mean PSNR to 21.61, while mean MAE is 17.36. Its generated edge-continuity score is much lower, 4.61, because low-resolution regression produces smooth neighboring outputs. This should not be over-read as cartographic correctness: the contact sheet shows that the model often captures broad water/land color fields but loses roads, labels, and fine symbol detail. The value of the baseline is that it gives the SCGM track a real learned generated-output condition and makes the metric trade-off visible.

The compact neural MLP baseline adds a fourth diagnostic condition. It uses the same 194 leakage-filtered train samples and produces 100 validation outputs. It reaches mean global luma SSIM 0.303, mean PSNR 17.96, mean MAE 30.73, and generated edge-continuity mean 12.13. This is better than color-stat retrieval on SSIM and comparable to multi-feature retrieval, but worse than the learned forest. Visually, the MLP outputs are noisy pastel low-resolution maps that do not recover roads, labels, or symbol structure. This negative result is useful: simply adding a small nonlinear neural regressor does not solve RS-to-map cartographic generation, and image metrics can still reward outputs that are not cartographically usable.

The local-context ridge baseline adds a fifth condition that is still CPU-friendly but more image-structured. It trains on 194 leakage-filtered tiles, yielding 198,656 low-resolution pixel samples, and produces 100 validation outputs. It reaches mean global luma SSIM 0.361, mean PSNR 21.19, mean MAE 17.54, and generated edge-continuity mean 8.08. This is weaker than the forest on SSIM and edge continuity, but stronger than the MLP on MAE, PSNR, and SSIM. The result is informative because a local receptive-field model can recover broad map-color fields more stably than the compact MLP, yet it still cannot infer long-range roads, labels, or cartographic topology.

The convolutional filter-bank ridge baseline adds a sixth condition and a stronger image-structured diagnostic. It trains on the same 194 leakage-filtered tiles, yielding 794,624 low-resolution pixel samples with 52 fixed convolutional and local-context features per pixel, and produces 100 validation outputs. It reaches mean global luma SSIM 0.347, mean PSNR 20.75, mean MAE 19.15, and generated edge-continuity mean 6.24. Compared with local-context ridge, it improves edge continuity but worsens MAE and SSIM; compared with the learned forest, it remains smoother and less structurally faithful. Visual inspection of the contact sheet shows broad pastel terrain and water fields but little recovery of roads, labels, or symbol structure. The baseline therefore narrows the gap between local regression and a future trained CNN, while preserving the paper's central caution: convolutional image features can improve some continuity measures without producing cartographically usable maps.

The patch-embedding retrieval baseline adds a seventh, patchwise image-to-image condition. It builds a bank of 12,416 leakage-filtered train patches, represents each 64-by-64 validation tile as 64 remote-sensing patches, retrieves nearest train patches, and copies their paired map patches into a generated mosaic. It produces 100 validation outputs with mean MAE 16.34, mean PSNR 19.99, mean SSIM 0.274, and generated edge-continuity mean 11.40. The low MAE is the best among the current baselines, but the weaker SSIM and border continuity show that patch-level color transfer does not recover global cartographic structure. The result is useful precisely because it separates patchwise appearance matching from coherent map generation.

The tiny trained CNN adds an eighth generated-output condition and closes the most obvious lower-bound gap. It trains a five-layer fully convolutional network from remote-sensing RGB to map RGB on 194 leakage-filtered training tiles, using 14 epochs and a 64-by-64 output target. Training loss falls from 0.199 to 0.063, and the model generates 100 validation outputs with mean MAE 26.10, mean PSNR 18.47, mean SSIM 0.366, and generated edge-continuity mean 9.22. This is a genuine trained CNN baseline, not a fixed-filter surrogate. Its contact sheet nevertheless shows the same core cartographic problem: the model learns pale terrain and water fields but smooths away roads, labels, and symbol structure. The CNN therefore improves the experimental spine without invalidating the paper's caution. A trained image-to-image model can optimize low-resolution color and texture while still failing the cartographic details that make a map usable.

The mosaic neighbor-seam stress audit adds a ninth SCGM diagnostic layer. Instead of scoring each generated tile only against its target, it treats available adjacent validation outputs as a partial mosaic and measures the RGB discontinuity across shared generated borders. The audit finds 12 available adjacent generated pairs for each of the eight baselines. Target-map seams average 4.47 RGB absolute difference across the same pairs. Generated seams vary substantially: learned forest is closest at 4.61, convolutional filter-bank ridge reaches 6.24, local-context ridge reaches 8.08, tiny CNN reaches 9.22, patch-embedding retrieval reaches 11.40, neural MLP reaches 12.13, color-stat retrieval reaches 20.09, and multi-feature retrieval reaches 24.09. This confirms that seam behavior is measurable at the mosaic level, not only as a per-tile border statistic. It also reinforces the central caution: a low seam score can mean coherent cartographic continuation, but it can also mean over-smoothed output that has washed away roads, labels, and symbol detail.

This result supports RQ3. File coverage alone does not test map-generation behavior. The retrieval and learned baselines are deliberately modest, but they reveal the evaluation challenge clearly: a generated tile can improve one image metric while worsening another, and it can remain visually plausible while failing neighborhood continuity or losing map detail. The edge and mosaic-seam metrics therefore capture properties that pixel similarity metrics alone may miss, but the learned forest and convolutional filter-bank ridge also show that continuity can be artificially improved by over-smoothing, while the MLP and patch-embedding retrieval show that neural or patchwise image-to-image conditions can still fail cartographic structure. The leakage guard also shows that small deterministic subsets must be designed carefully, because train and validation manifests can contain overlapping tile identifiers.

### 6.3 Choropleth Geodata, Artifact QA, and Repair Benchmark

The choropleth linter detects two important raw geodata issues: one invalid geometry in `boundary.shp` and missing CRS metadata in `mainlandburn.shp`. The released map artifact audit finds 33 PNG files and 10 HTML files, with no empty or blank artifacts by file-level checks. Existing seed candidate runs show that rule-based checks can identify both successful output generation and intentional wrong-column failure.

The deterministic reference baseline produces all required artifact classes from the released data: `map_static.png`, `map_interactive.html`, `time_series.png`, and `diagnostics.json`. Its diagnostics record 18 mainland district features, CRS normalization from missing metadata to EPSG:4326, repair of the invalid boundary geometry, 21 annual CSV rows from 2002 to 2022, and 2017 as the maximum burned-area year. This establishes that the benchmark data are sufficient for successful execution and that LLM-code failures are not caused by missing benchmark inputs.

This result is important for interpreting the LLM-code benchmark. If generated scripts fail, the failure cannot be dismissed as a missing-data problem. A deterministic script using the same benchmark inputs can create complete artifacts. The reference baseline therefore acts as a positive control for the benchmark environment.

**Expanded choropleth code-generation benchmark.**

We created an expanded choropleth reliability benchmark with 12 prompts spanning static choropleths, CRS/geometry robustness, join diagnostics, cartographic design, interactivity, time series, and adversarial column validation. We ran two reproducible coding models, `qwen2.5-coder:7b` and `deepseek-coder:6.7b`, under two prompting conditions: Basic and cartographic Rules. For `qwen2.5-coder:7b`, all 24 generated scripts passed static safety scanning, but none executed successfully. Basic prompting produced very low rubric scores, averaging 0.059 across the 12 tasks, mostly because scripts hallucinated file names, file assumptions, and schema. Rules prompting improved grounding and geospatial awareness, averaging 0.490, but still failed execution in every task through missing imports, incorrect geometry-repair APIs, deprecated GeoPandas arguments, wrong merge keys, or unresolved schema assumptions.

For `deepseek-coder:6.7b`, 22 of 24 generated scripts passed static safety scanning; the two unsafe cases were syntax errors in Basic multi-output/time-series tasks. Among the 22 executed scripts, two returned exit code 0: Basic interactive tooltips and Rules static full-layout. However, both still failed required artifact checks, because they did not produce all expected files. The model-mode aggregate therefore shows a sharp distinction between execution success and complete cartographic artifact success: deepseek produced 2 nominally successful executions, but zero complete benchmark artifacts. Rules prompting again improved partial scores, with mean score 0.501 for deepseek rules versus 0.176 for deepseek basic.

The dominant error taxonomy across failed benchmark and repair runs is missing imports, schema hallucination, CRS/geometry handling, hard-coded file assumptions, and wrong filenames. We first ran a one-pass 7B LLM repair pilot on the first three qwen prompts using runtime stderr and the verified data profile. Repair improved partial scores for Basic scripts by replacing some brittle file assumptions and adding known inputs, but still produced no successful executions. Several repaired scripts retained schema hallucinations or introduced new errors such as missing `os` imports, incorrect geometry repair code, or invalid merge keys.

We then ran a stronger one-pass repair condition using `qwen2.5-coder:32b` on all 46 current failed or incomplete LLM-generated runs. All 46 repaired scripts passed static safety scanning. Six repaired tasks reached complete benchmark success after execution and artifact scoring: two deepseek Basic tasks, two deepseek Rules tasks, one qwen Basic task, and one qwen Rules task. The repair condition raised mean scores substantially relative to initial generation, but it still left most tasks incomplete and created no valid interactive HTML artifact under the rendered artifact QA checks. This result sharpens the design claim: LLM repair is useful, but it must be validator-gated and scored after execution, because many repairs improve grounding without satisfying the full cartographic artifact contract.

The iterative validator-gated sweep tests whether explicit feedback can close some of these remaining gaps. We selected all 40 one-pass 32B repairs that remained incomplete and allowed up to three additional repair iterations per case. All 89 attempted iterative scripts passed the static safety scan. Twenty-five of the 40 cases became complete: 10 after the first iterative attempt, 11 after the second, and 4 after the third. The recovered set includes CRS repair, geometry repair, wrong-column guard, static burned-area and number-of-fires maps, all four colorblind-safe design cases, three interactive-tooltip tasks, two quantile-classification tasks, three time-series report tasks, and one static-plus-interactive multi-output task. The remaining 15 cases improved or remained near complete but still failed one required check or artifact contract, most commonly execution success, static PNG creation, diagnostic JSON creation, or interactive HTML creation. This result is diagnostic rather than triumphant: validator feedback can recover many artifact contracts, including some previously stalled multi-output cases, but repeated repair still stalls on persistent schema, serialization, rendering, multi-output, and interactivity errors.

To test whether this repair behavior is specific to the 32B repair model, we also ran a matched smaller-model suite with `qwen2.5-coder:14b`, `qwen2.5-coder:7b`, and `deepseek-coder:6.7b` on the same eight near-miss cases selected from the incomplete one-pass repair pool. The two smaller Qwen models each produced 14 safety-clean repair attempts and completed three of the eight cases after up to two iterations, but they completed different cases and reached different mean final scores: 0.829 for 14B and 0.808 for 7B. The 14B model completed geometry repair and wrong-column guard tasks; the 7B model completed one CRS-repair case and two wrong-column or missing-CRS cases. DeepSeek completed none of the eight cases and only four of ten attempted scripts passed the static safety/syntax gate, mostly because generated repairs were syntactically invalid; its mean final score was 0.204. Because the matched suite uses a smaller subset and fewer iterations than the 32B full sweep, it should be read as repair-model sensitivity evidence rather than a leaderboard against 32B. It nevertheless strengthens the paper's repair-loop argument: validator feedback can help multiple local coding models, but the completion boundary depends on model family, model capacity, case selection, syntax reliability, and artifact contract complexity.

Rendered artifact QA reinforces this distinction. The deterministic reference baseline passes all artifact checks, with two nonblank PNG images, one Leaflet/GeoJSON HTML map, and one valid diagnostic JSON. Across the 46 clean benchmark runs for qwen and deepseek, only one generated artifact is created: a small valid `diagnostics.json` from deepseek Rules C003. No initial generated run produces a nonblank PNG or valid interactive HTML artifact. The 32B repair condition creates 11 existing artifacts, including five nonblank images and six valid diagnostic JSON files, but still no valid HTML artifact under the Leaflet/GeoJSON check.

The screenshot-level QA layer confirms the same pattern visually. The deterministic reference baseline passes 3/3 screenshot checks. The validator/reference condition passes 36/36 checks: 12 static PNGs, 12 time-series PNGs, and 12 rendered interactive HTML screenshots. The 32B repair condition passes five static-map screenshot checks, corresponding to the subset of repairs that generated inspectable PNG maps, but it passes no interactive HTML or time-series screenshot checks. Initial qwen and deepseek outputs pass zero screenshot-level checks. These results make the gap between executable code, file-level artifacts, and visually inspectable cartographic outputs explicit.

The VLM cartographic-quality pilot adds a qualitative visual layer to the screenshot-passing subset and exposes evaluator sensitivity. Granite gives the validator/reference group the highest mean quality score, 0.700 across ten artifacts, all judged usable with minor issues. It gives the deterministic reference group a mean score of 0.567 and the 32B repair group 0.478, with three usable, one weak, and one failed repair screenshot. qwen2.5vl reviews the same 18 artifacts much more severely: it gives means of 0.400 for the deterministic reference group, 0.220 for the repair group, and 0.300 for validator/reference screenshots. It still marks all ten validator/reference screenshots as usable with minor issues, but marks all five repair screenshots as failed and flags the time-series reference as failed. The disagreement reinforces the need for calibrated VLM prompts or human labels. At the same time, both VLMs preserve the same broad ordering: validator/reference artifacts are more consistently usable than LLM-repair static maps. The pilot therefore demonstrates that the evaluation stack can move beyond blankness and parseability toward map-specific visual review, while also showing why VLM scores must not be treated as expert ground truth.

The paired agreement analysis sharpens this interpretation. The two VLMs agree on 13 of 18 exact choropleth verdicts and 14 of 18 usable-versus-below decisions, despite large differences in numeric score scale. The validator/reference artifacts have 10/10 exact verdict agreement, while the repair artifacts have only 1/5 exact verdict agreement. For MapGenerator captions, the opposite pattern appears: feature-level agreement is high at 73/79 comparable judgments, but exact semantic-support verdict agreement is only 3/20. A separate judge-robustness audit confirms that Granite and qwen2.5vl are the only local models in this run that provide complete schema-conformant reviews for both tasks; candidate models either cover only part of the caption panel or fail the choropleth schema. These results suggest that VLMs are more stable when judging coarse rendered-map usability than when judging whether a caption is fully semantically supported by a map image, and that evaluator schema adherence must be measured rather than assumed.

The calibrated multi-judge consensus confirms the same asymmetry. For MapGenerator, only 1 of 20 caption items has high-confidence coarse consensus, while 15 are medium-confidence and 4 are low or unstable. For choropleth cartographic quality, all 18 reviewed artifacts have at least two usable judges, 13 reach high-confidence consensus, 4 are medium-confidence, and 1 remains low or tied; 13 have positive usable-or-minor consensus, 4 fall below the usable threshold, and 1 is discordant or tied. The consensus layer therefore narrows the remaining evaluator-validity gap for rendered-map QA while showing that caption fidelity still needs human or independent model validation before semantic-error rates are claimed.

To make this evaluator sensitivity operational, we build an adjudication ledger rather than treating VLM agreement as truth. The ledger classifies paired VLM cases into stable low-priority cases, high-priority calibration cases, and urgent human-adjudication cases. For MapGenerator, 17 of 20 paired cases are urgent because the two complete VLMs disagree on supported-versus-below-supported status even when many visible-feature judgments match. For choropleth artifacts, 4 of 18 are urgent, while 10 validator/reference artifacts are stable low-priority positive controls under exact and coarse verdict agreement. This prioritization turns the VLM pilot into a sampling plan for human validation: it identifies where expert judgment is most needed and prevents the manuscript from over-claiming model-generated labels.

As a positive-control repair target, we additionally generated a deterministic validator/reference condition for all 12 choropleth tasks. This condition is not counted as LLM success: it uses the verified data profile and validator rules to write task-specific reference scripts. All 12 validator/reference scripts pass safety scanning, execute successfully, and produce complete required artifacts, yielding 48 valid outputs across static maps, interactive maps, time-series figures, and diagnostic JSON files. The result shows that the benchmark tasks are repairable when schema, CRS, geometry, and output contracts are enforced deterministically. It also establishes an upper-bound target for future LLM-based validator-gated repair loops.

This result supports RQ4. Rule-guided prompting improves partial grounding, but not enough to produce complete valid artifacts in this benchmark. The gap between execution success and artifact success is especially revealing. Deepseek has two scripts that return exit code 0, yet neither produces a complete set of requested outputs. In cartographic workflows, a successful process is not merely one that exits without an exception; it must create the requested map artifact with the expected semantics and metadata.

## 7. Discussion

### 7.1 Artifact-Chain Reliability Across Paradigms

The experiments show that reliability cannot be assessed at one point in the workflow. A dataset can have complete image files but weak caption constraints. A tile dataset can have complete base pairs but incomplete cascade references. A choropleth output can exist as a PNG while the underlying geodata have missing CRS. Evaluation must therefore follow the artifact chain.

This is the central lesson of the study. A final map-like image is only one endpoint. The chain before and after it determines whether the output can be trusted. For scientific use, a generated map should be traceable to input data, reproduce a defined task, preserve spatial constraints, and expose validation results. Without that chain, the output is difficult to audit even if it is visually plausible.

**Cross-paradigm failures are different but comparable.**

Text-to-map systems fail semantically. Remote-sensing-to-map systems fail spatially and across tile boundaries. LLM-code systems fail through execution, schema, CRS, join, and design errors. These failure modes are different, but they can be compared through a shared reliability frame: data grounding, spatial faithfulness, artifact validity, cartographic completeness, and reproducibility.

This shared frame answers RQ5. It does not force all paradigms into the same metric. Instead, it maps each paradigm to artifact-appropriate metrics. Caption review is appropriate for text-to-map data. Edge continuity is appropriate for tiled RS-to-map outputs. Execution and artifact QA are appropriate for generated GIS code. The comparison happens at the level of reliability dimensions, not at the level of one universal score.

To make the comparison auditable, we synthesize a cross-paradigm reliability matrix across seven shared dimensions: release reproducibility, data grounding, spatial faithfulness, artifact validity, cartographic completeness, evaluator robustness, and repairability. The scores are diagnostic 0-3 ratings derived from local evidence rather than universal quality scores. Text-to-map image data have a mean diagnostic score of 1.29 across the seven dimensions: file validity is strong, but semantic grounding, evaluator robustness, and repairability remain weak. Remote-sensing-to-map tiles have a mean score of 2.00: base-pair grounding and generated-output validity are strong, but cartographic completeness remains weak because smooth image outputs still miss roads, labels, and topology. LLM-generated choropleth maps have a mean score of 2.14: initial generation is brittle, but the editable code/artifact chain supports validation, repair, and positive-control comparison. This matrix makes the central claim more precise: each paradigm is reliable in different parts of the artifact chain, and the weakest dimensions determine what evidence is still needed before generated maps can be trusted.

### 7.2 Reproducibility, Repairability, and Benchmark Design

Public repositories often provide files, but files alone do not reproduce claims. The MapGenerator train-count mismatch, SCGM cascade-reference coverage issue, and choropleth CRS problem are examples of small but consequential gaps. A reproducibility audit should be standard for Geo-GenAI papers.

The practical implication is that Geo-GenAI releases should include machine-readable manifests. For image-caption datasets, manifests should include split definitions, image checksums, caption versions, and basic feature/caption statistics. For tiled map-generation datasets, manifests should include z/x/y indexing, neighbor availability, reference-scale availability, and train-validation overlap checks. For LLM-code map outputs, releases should include prompts, model versions, generated code, execution logs, output artifacts, and validator reports.

**Toward repairable cartographic generation.**

LLM-code map generation has one major advantage over pure image generation: many failures are diagnosable and repairable. If a CRS is missing, a field is wrong, or a geometry is invalid, a linter can generate structured feedback. This suggests a practical path toward reliable map agents: generate, execute, lint, repair, and revalidate.

However, the repair loop must be evaluated as a system, not as a text edit. The 7B repair pilot improves partial rubric scores for some prompts but does not produce valid map artifacts. The stronger 32B one-pass repair condition produces six complete tasks, showing that LLM-based repair can recover some failures when given runtime feedback and a verified data profile. In contrast, the deterministic validator/reference condition reaches 12/12 complete tasks, proving that the same benchmark can be satisfied when repair is driven by explicit data contracts and validation rules. This means the next research question is not whether the tasks are feasible, but how close LLM-based repair can get to the deterministic positive control without manual oracle knowledge. A repair loop that makes code look more grounded while still failing execution has not improved cartographic reliability.

**Benchmark design and general positioning.**

The experiments suggest four benchmark-design recommendations.

First, every Geo-GenAI benchmark should include a positive control. The choropleth reference baseline shows that the benchmark data and execution environment can produce the requested artifacts. Without such a control, model failure and benchmark failure are difficult to separate.

Second, benchmark scoring should distinguish partial credit from success. Partial grounding is useful diagnostically, but final claims should be based on complete artifact validity.

Third, train-validation leakage checks should be explicit in tiled datasets. The SCGM retrieval baseline initially revealed exact tile-id candidates in the small train/validation subset. A leakage guard changed the interpretation of the baseline and should be part of any retrieval or nearest-neighbor evaluation.

Fourth, proxy review should be labeled as proxy review. The MapGenerator visual proxies are useful for triage, but they are not substitutes for human or VLM semantic labels. Treating them honestly makes the manuscript stronger, because it separates current evidence from planned validation.

Fifth, repair loops should be evaluated as interventions, not anecdotes. A repair prompt that fixes one script is useful, but it does not prove that an LLM can maintain a cartographic artifact contract. The repair loop needs a starting state, a feedback payload, a safety gate, an execution gate, a scoring gate, and a stopping rule. The near-miss iterative pilot follows this structure and shows both recoveries and stalls. The stalled cases are especially informative: they show where feedback about missing files or runtime errors is still insufficient to correct deeper schema assumptions.

Sixth, benchmark outputs should include negative evidence. Failed scripts, stderr tails, unsafe generations, blank screenshots, and incomplete artifacts are not noise to be discarded. They are the evidence that distinguishes map-like generation from trustworthy cartographic production. For applied cartography, this is arguably more important than a gallery of successful examples, because deployment depends on knowing how a workflow fails and how reliably those failures can be detected.

Seventh, cross-paradigm comparison should report dimension-level evidence rather than a single winner. The reliability matrix shows why: LLM-code maps score highest on repairability, RS-to-map tiles score highest on base-pair grounding and deterministic generated-output diagnostics, and text-to-map image data score highest on file-level artifact validity. None of these strengths transfers automatically to the other dimensions. A useful benchmark should therefore report where each artifact family is strong, where it is weak, and which validation layer would change the claim.

**General positioning.**

The manuscript is best positioned as an evaluation and reliability paper for GIScience/cartography rather than as a model-proposal paper. Its novelty is not a new generator architecture, but a cross-paradigm audit that connects release reproducibility, caption grounding, tile continuity, executable GIS code, rendered artifacts, visual QA, and repairability. This positioning fits journals that value methodological rigor, reproducible geospatial workflows, and critical assessment of emerging GeoAI systems.

The contribution claim should be conservative and evidence-led: current Geo-GenAI map-generation artifacts are promising but uneven, and trustworthy use requires artifact-specific validation layers. The paper should avoid claiming that locally run models are representative of all frontier models, that VLM labels are equivalent to expert cartographic judgment, or that deterministic retrieval baselines reproduce diffusion models. Instead, it should emphasize a reusable evaluation design and the empirical finding that failures become visible only when the full artifact chain is audited.

For journal submission, the manuscript should reserve the main text for the cross-paradigm argument, key tables, and diagnostic figures, while moving detailed prompt lists and exhaustive run tables to supplementary material. The current evidence tables are valuable as supplementary evidence, but a polished article should keep the printed display set small and use an online appendix for the full audit trail.

## 8. Limitations

The evidence package reports local audits and an expanded local LLM-code benchmark, so its claims are intentionally scoped to reproducible public artifacts and locally recorded model runs. The MapGenerator caption audit includes deterministic proxy review, CLIP-style embedding scores for 200 proxy-reviewed image-caption pairs, 110 local VLM review attempts across six vision-model configurations, 58 complete non-error reviews, a paired agreement analysis over the 20 common Granite/qwen2.5vl reviewed pairs, a calibrated multi-judge consensus over schema-conformant reviews, and a judge-robustness audit showing which candidate VLMs fail schema-constrained evaluation. The SCGM experiment includes color-stat and multi-feature generated-output retrieval baselines, a lightweight learned random-forest RS-to-map baseline, a compact neural MLP baseline, a local-context ridge baseline with an explicit 3-by-3 low-resolution receptive field, a convolutional filter-bank ridge baseline with fixed multiscale edge/blur/local-context features, a patch-embedding retrieval baseline that copies locally matched train-map patches, a tiny trained CNN baseline that maps remote-sensing RGB to map RGB, and a mosaic neighbor-seam stress audit over adjacent generated validation tiles. These baselines do not replace the official SCGM diffusion-style reproduction with cascade references and scale conditioning, but they establish leakage-filtered generated-output conditions with different failure modes. The expanded choropleth benchmark covers two local models across 12 prompts and two prompting modes, a 7B repair pilot, a 32B one-pass repair condition, a 40-case iterative validator-gated incomplete-case repair sweep through a third iteration, a matched Qwen 7B/14B and DeepSeek 6.7B repair-model suite over eight near-miss cases, a deterministic validator/reference positive control, screenshot-level visual-proxy QA, 54 VLM cartographic-quality review attempts over 18 screenshot-passing artifacts, a paired VLM agreement analysis over the 18 common Granite/qwen2.5vl artifacts, calibrated multi-judge consensus over schema-conformant reviews, and a judge-robustness audit showing that the third candidate choropleth judge fails schema adherence on most artifacts. Initial LLM generation produces zero complete valid benchmark artifacts; the 32B one-pass repair condition produces six complete tasks and five screenshot-passing static maps; the iterative sweep completes 25 of the 40 remaining incomplete one-pass repairs; the Qwen 7B and 14B matched suite each complete three of eight near-miss cases; the DeepSeek 6.7B suite completes zero of eight cases; and the validator/reference condition produces 12 complete tasks and 36 screenshot-passing visual artifacts. The validator/reference condition should be interpreted as an oracle-style upper bound for the repair pipeline, not as evidence that local LLMs can self-repair. The strongest remaining empirical upgrades are expert human agreement for caption and cartographic-quality labels, an official or cascade-conditioned diffusion-style RS-to-map reproduction, and a broader full-case repair-model suite.

Several additional threats to validity should be addressed before submission. The first is dataset representativeness. The evidence package contains important public artifacts, but it is not a complete census of Geo-GenAI map-generation systems. The second is model representativeness. Locally run coding and vision models are useful for reproducible experiments, but they may understate or overstate the behavior of proprietary frontier systems. The third is metric validity. Image proxies, edge continuity, and rubric scores are informative, but each captures only part of cartographic quality. The fourth is evaluator validity. Single-VLM pilots can be brittle and may miss map elements that humans would recognize. The fifth is task validity. The Portugal wildfire choropleth benchmark is concrete and useful, but it does not cover all thematic mapping tasks, projections, classification schemes, or interaction designs.

These limitations do not invalidate the audit; they define the boundary of its claims. The paper's strongest claim is methodological: Geo-GenAI evaluation should be artifact-aware, reproducible, and repair-oriented. The empirical results support that claim across the current evidence package, while the remaining upgrades would improve reviewer confidence in evaluator validity, model representativeness, and RS-to-map baseline strength.

## 9. Additional Strengthening Experiments

The next experiments are:

1. Expand the matched Qwen 7B/14B and DeepSeek repair-model suite from eight near-miss cases to a broader full-case design and compare all models against the deterministic validator/reference positive control.
2. Extend the 18-artifact choropleth calibrated VLM consensus into expert human cartographic-quality labels with explicit inter-rater agreement.
3. Extend structured lint feedback from deterministic validation into model-generated repair attempts.
4. Extend the MapGenerator calibrated VLM consensus and completed CLIP screening with expert human labels or another schema-stable VLM judge that also passes the choropleth review contract.
5. Extend the SCGM retrieval/forest/MLP/local-context/convolutional-filter/patch/tiny-CNN baselines with an official or cascade-conditioned diffusion-style reproduction.
6. Run a small human or VLM agreement study on flagged MapGenerator and choropleth outputs.

## 10. Conclusion

Geo-GenAI map generation is moving quickly, but trustworthy cartographic generation requires more than plausible images. This paper reframes generated maps as artifact chains and shows how public Geo-GenAI artifacts can be audited for reproducibility, semantic fidelity, geospatial integrity, tile continuity, rendered-output validity, visual QA, and repairability. The results reveal both promise and fragility: large datasets and rich artifacts are available, but metadata gaps, caption underspecification, incomplete cascade references, geospatial data issues, brittle code generation, and evaluator disagreement remain. The proposed cross-paradigm reliability framework provides a path from impressive demonstrations toward reproducible, validated, and repairable cartographic AI.
